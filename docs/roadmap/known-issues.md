## Historical notes before the current work

- `installer/setup-env.ps1` is the official bootstrap. With `uv` and Python 3.12 it installs `installer/requirements-core.txt`, `requirements-qwen.txt`, `requirements-stt.txt`, and `requirements-xtts.txt` into `.venvs/core`, `.venvs/qwen`, `.venvs/stt`, and `.venvs/xtts`. Qwen depends on `realtimetts-qwen-native==0.2.0`. A silent clean install of `SpeechStudio_0.1.0_Setup.exe` on 24 Nov 2026 landed in `C:\Program Files (x86)\XYZ-Productions\Speech Studio`. `setup-env.ps1` exited 0 and created those `.venvs`. A silent `/DIR` to a custom folder was ignored, so the files did not follow the requested path. The template default remains `{autopf}\XYZ-Productions\Speech Studio`.
- `npx tauri build` still emits MSI and NSIS bundles. Those bundles do not install the Python environments. The Inno Setup program `installer/Output/SpeechStudio_0.1.0_Setup.exe` is the installer that runs `setup-env.ps1`. See [docs/app/instalador.md](../app/instalador.md).
- Live Captions routes WASAPI process-loopback audio to the selected STT (local faster-whisper or an external endpoint). A real capture session has not been tried yet. See [docs/app/live-captions.md](../app/live-captions.md).
- Linux CI builds the shell (`cargo build` on Ubuntu 24.04, debug, not packaged). There is no AppImage or `.deb`. macOS CI runs `cargo check` and clippy; there is no macOS bundle. The tray icon (primary click opens the menu; macOS marks it as a template) and the toasts (`notify-send` on Linux, `osascript` on macOS) are in the source and have not been tried on those desktops. Toast text follows `settings.language` (`en` or `es`).
- The XTTS v2 worker, `runtime/envs/xtts` (legacy `.venvs/xtts` still read), and the local checkpoint weights are present. `requirements-xtts.txt` pins `coqui-tts==0.28.0` and `six==1.17.0`. A load failed once because `six` was missing, until `pip install six`. Real synthesis may still be validating. Checkpoint weights stay out of the repo (Coqui Public Model License). Parakeet, Moonshine, and Fish Audio stay in the catalog with `runtime_supported: false`.
- CrispASR bridge (`backend/orchestrator/crispasr.py`) synthesizes Piper / F5 GGUF when `runtime/bin/crispasr(.exe)` (or `CRISPASR_BIN`) is present; catalog then flips those engines to `runtime_supported`. Kokoro stays catalog-only until a GGUF voice pack is on disk (CrispASR has no `-m auto` for Kokoro). Place the binary with `scripts/fetch-crispasr.ps1` or see `runtime/bin/README.md`. STT migration to CrispASR is still pending.
- GitHub Sponsors for `xyz-rainbow` may not be enabled (the sponsors URL currently redirects to the organization profile). Funding links in `.github/FUNDING.yml` still include Patreon, Ko-fi, Buy Me a Coffee, and PayPal.
